## 文档职责

本文处理 #574 中大型仓库的只读查询性能退化。目标是让纯查询命令不触发仓库变更操作的前后工作区快照，同时保留真实变更命令的操作记录和安全边界。

### 已合入实现的计划对账

截至 2026-10-01，PR #586 已合入 branch 查询分类（v0.30.9，BRL-01 `done/complete`）；PR #587 已将 tag/remote/reflog/notes 查询分类合入 main，代码与网站文档已提交，状态为 v0.30.10 `remote-pending`（BRL-02）。两组实现合计覆盖维护者确认的五个命令族，属于本计划范围内的既有实现。

这些实现先于 QP-00/QP-01 计划门落地，不代表 QP-00 要求的 debug 基线、完整矩阵和性能验收已经完成。为避免重复实现，QP-01 在本计划中的验收/发布收口工作仍列 `pending`（代码实作已由前序 PR 提前交付，不代表该计划卡已开始）；QP-00 和计划评审门满足后，仅核验既有实现、完成 debug 性能验收和发布收口，不重复改写已合入的分类代码。`log`/`rev-list` 遍历仍移交 #478，快照 stat 短路不属于本计划。

### 适用范围

- `branch`、`tag`、`remote`、`reflog`、`notes` 查询形态的 Operation Log 分类。
- 只读/变更形态判定、操作记录副作用回归、相关命令文档与兼容说明。
- 在当前候选树建立可重复的性能基线并验证修复收益。

### 非目标

- `log` / `rev-list` 的历史遍历性能：转交 [`issues/478.md`](478.md) 评估，不在本计划改 `src/command/log.rs`。
- `.libra/object-index-repair-locks` 残留文件清理：仍受 `plan-20260918.md` 的 `469-DEFER-01` 约束；Issue #574 也未将其认定为本次耗时主因。
- 改造快照算法、工作区扫描器、锁实现或 Operation Log 数据模型。
- 仅因命令名字或 flag 外观将尚未逐项核实的调用归为只读。

### 成功定义

- 只读查询不创建持久操作、不执行前后工作区快照，且不改变其输出和退出状态；仓库命令仍保留 `Repository` scope。
- 相同的查询与真实变更形态通过回归矩阵证明分类边界正确。
- 在同一当前仓库数据集与相同工具链/debug profile 下，纯查询主行为断言为 `operation`、`operation_journal` 行数不变且无 workspace snapshot 写入；性能辅证按 5 次预热后采样 5 次：中位数低于 5 秒，且较修复前中位数至少下降一个数量级；修复后不比既有 ReadOnly ref 查询慢一个数量级。
- Issue 中的独立 `log -1` 慢路径有明确接收位置，不被误认为本计划已修复。

## 已决议设计决策

### ADR-QP-01: 只读判定必须按完整参数形态

- **Status:** Confirmed by Issue maintainer; implementation remains gated by plan review and dependencies
- **Context:** 同一个顶层命令同时含查询与变更行为；按 `Commands::Branch(_)` 等顶层 variant 一律绕过操作边界会把写操作错误分类。
- **Decision:** 维护者确认 Operation Log v2 只记录会改变仓库状态的操作。对 QP-00 范围矩阵中已确认不改变本地仓库状态的完整参数形态，`operation_class_for_command` 返回 `MutationClass::ReadOnly`；`command_scope` 保持 `Repository`，保留 repository preflight 与拒绝语义。外部只读网络查询可纳入（如 `remote show`、`remote prune --dry-run`），但必须确认不改本地 ref/config。未列明、组合或实现仍有副作用的不确定形态沿用现有 mutation class。
- **Alternatives considered:** 按命令名称整体归为只读会使真实变更绕过 Operation Log v2，拒绝。根据命令运行结果是否发生变化再决定是否写 snapshot，无法避免边界成本且会改变 Operation Log 契约，拒绝。
- **Consequences:** 纳入的纯查询不新增 operation、journal 或 workspace snapshot；创建/删除/重命名/复制/upstream 修改/reset 等变更形态保留持久边界。`branch --set-upstream-to` 维持现有 ReadOnly 分类。该修复恢复既有契约，不新增查询审计承诺；覆盖参数边界和 dry-run 实际副作用。
- **Revisit when:** QP-00 的实际解析矩阵或维护者确认的操作记录契约与上述判定不一致。

### 维护者确认的形态范围

以下是 QP-00 矩阵的起始范围，依据 [Issue maintainer 2026-09-29 评论](https://github.com/libra-tools/libra/issues/574#issuecomment-5891380761)；执行时仍须对照当前 CLI parser 与实现，尤其验证 dry-run 确实无写入。网络访问与本地仓库变更分开判断：网络只读不等同于本地仓库写入。

| 命令族 | 纳入 ReadOnly 的查询形态 | 仍使用持久 operation 边界的变更形态 |
|---|---|---|
| `branch` | 无参数列表、`-l`、`-r`、`-a`、`--show-current`、`--contains` / `--no-contains`、`--points-at`、`--merged` / `--no-merged`、`--sort`、`--ignore-case`、`--format`、`--column` / `--no-column`、`-v`。`--contains`/`--merged` 的遍历成本不属于本卡优化 | 创建、`-d`/`-D`、`-m`、`-c`/`-C`、实际改变 upstream 的 `--set-upstream-to`、`--unset-upstream`、`--edit-description`、`reset`。仅当前 upstream 已匹配的幂等 `--set-upstream-to` 保持已有 ReadOnly 行为 |
| `tag` | 无参数列表、`-l`、`-n`、`--points-at`、`--contains` / `--no-contains`、`--merged` / `--no-merged`、`--sort`、`--column` / `--no-column`、`--verify` | 创建/强制更新及删除；`-a`、`-m`、`-F`、`-e`、`-s`、`-f` 等写形态 |
| `remote` | `-v`、`show`（含 `--no-query`）、`get-url`、`prune --dry-run`；其中 `show` 和 `prune --dry-run` 可访问网络，但不应改本地 ref/config | `add`、`remove`、`rename`、`set-url`、`update`、`set-branches`、`set-head` 及非 dry-run `prune` |
| `reflog` | 无子命令（等价 `show HEAD`）、`show`、`exists`、`expire --dry-run`；dry-run 若实现有数据库写入则不得纳入 | `delete` 及非 dry-run `expire` |
| `notes` | `list`、`show`、`get-ref`、`prune --dry-run`；dry-run 若实现有写入则不得纳入 | `add`、`append`、`edit`、`copy`、`remove`、`merge` 及非 dry-run `prune` |

任何混合参数、未列出形态或实测有副作用的形态保持原分类。参数矩阵的验证覆盖实际解析结果、命令副作用及分类结果，不能仅按命令名称归类。
